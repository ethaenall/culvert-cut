# Culvert Cut specialist

A small local model for explaining WRIA 8 fish-passage evidence and auditing claims about inventory snapshots. It is not a fish-passage engineer, a water-quality sensor, or a restoration-outcome predictor.

## Training that actually ran

- Base: `Qwen/Qwen2.5-1.5B-Instruct` (1,543.714M model parameters as reported by MLX).
- Backend: MLX LM 0.31.3 on an Apple M5 Pro with 48 GiB unified memory.
- LoRA: all 28 transformer layers, q/k/v/o projections, rank 16, scale 2 (equivalent to alpha 32 / rank 16), dropout 0.05.
- Run: 770 optimizer steps, batch 4, learning rate 0.0002, sequence limit 768, completion-only loss, seed 2026. Approximately one traversal of 3,078 training pairs; MLX's batching determines the exact sample order.
- Peak memory reported by the trainer: 11.130 GB. Final validation loss: 0.548 on five validation batches. Loss is not an accuracy score.
- Final adapter: `adapter/mlx/adapters.safetensors`. Configuration and SHA-256 hashes are recorded in `adapter/mlx/training_run.json`. The complete trainer output is in `data/specialist/training_log.txt`.

## Dataset and boundaries

3,078 training pairs mix record explanations, claim audits, official-source summaries, and refusal examples. WDFW records retain their actual identifiers and values. No synthetic locations or changed official field values were used. Claims can deliberately conflict with those records to create negative examples. Labels and answers were generated by explicit rules, not expert annotation.

The test comprises 120 cases across 40 Site IDs, all excluded from training and validation. Another 20 sites form the 80-example validation split. Site splitting is based on SHA-256 ordering and is reproducible. The test uses different wording but related task families; it measures generalization to unseen sites and prompt variants, not arbitrary scientific reasoning.

An earlier 0.5B experiment exposed weak explanations despite improved verdict labels. That experiment's 40 test sites were reclassified as development data and excluded from this run. The final 1.5B experiment uses 40 fresh test sites and varied training wording. The earlier raw evaluation is preserved under `data/experiments/v1/`; its score is not directly comparable because the test split changed.

Task labels:

- **Supported:** an explicit supplied field backs a statement about the record.
- **Contradicted:** an explicit known field conflicts with the claimed value.
- **Insufficient / Not established:** the required observation, connectivity assessment, chemistry measurement, or spatial join is missing. An unknown passage status is not automatically a contradictory observation.

A supported statement concerns the supplied snapshot. It is not a claim that the site remains in that condition today. Fish use is not a direct observation count; modeled potential is not confirmed occupancy; one passable crossing does not establish full upstream connectivity.

## Evaluation

Measured results: **40/120 correct verdicts for the base (33.3%), 116/120 for the adapter (96.7%)**. Exact citation-array compliance was 0/120 and 120/120 respectively. The base used empty arrays or source URLs rather than the requested source-ID strings; this is a schema failure, not proof of absent citations. Of the base outputs, 55 used URL arrays, 49 used empty arrays, and 16 used non-JSON prose. All 16 prose outputs also gave the wrong verdict on inspection. All four specialist verdict errors are published. Each incorrectly abstains when a claim says total but the source says partial; their explanations incorrectly invoke upstream classification. A separate 40-site explainer check on development records excluded from training produced no unknown Site IDs and cited every expected identifier; it does not establish full prose accuracy.


| Task family | Correct specialist verdicts |
|---|---:|
| Matching passage field | 40/40 |
| Conflicting passage field (including unknowns) | 36/40 |
| Upstream connectivity overreach | 10/10 |
| Direct-observation overreach | 10/10 |
| Live-chemistry overreach | 10/10 |
| Unverified impairment intersection | 10/10 |

Reference labels comprise 40 supported, 37 contradicted, and 43 insufficient cases. Always choosing the most common label would score 43/120 (35.8%).

Run `scripts/evaluate_specialist.py` in base and adapter modes, then publish. The public `model-evaluation.json` contains every prompt, context, expected label, unedited generated output, parse result, and generation time. The website's Evidence lab exposes successes and failures.

Both models receive the identical system message, task instruction, and site context. Decoding is greedy with a 160-token limit. Each case receives one generation. No templates, retries, generated-answer repairs, or safety-filter substitutions contribute to the score. Markdown fences may be stripped for JSON parsing; output content is never changed.

We separately count correct verdicts and exact source citations. A combined pass requires both. A formatting failure counts as a failure. These metrics do not prove the factual validity of every explanation. A citation can point at a source that does not support the prose. The benchmark is narrow, programmatically labeled, and not independently expert-reviewed. Raw outputs make that limitation inspectable.

## Reproduce on Apple silicon

```sh
python3.11 -m venv .venv-mlx
source .venv-mlx/bin/activate
pip install -r requirements-mlx.txt
python scripts/build_specialist.py
MODEL_NAME=Qwen/Qwen2.5-1.5B-Instruct python train.py --backend mlx
python scripts/evaluate_specialist.py --mode base
python scripts/evaluate_specialist.py --mode adapter
python scripts/evaluate_specialist.py --mode publish
```

`train.py` automatically chooses MLX on Apple silicon. The original CUDA PEFT/TRL route remains available with `--backend peft` in a separate environment installed from `requirements.txt`. The formats of MLX and PEFT adapters differ; do not interchange their directories. Model weights download from Hugging Face; no external inference API is used.

## Live use and distribution

The GitHub Pages site is static. Its model trials replay saved real generations and are labeled accordingly. Running a new claim requires the local Python service; it re-reads the selected Site ID from canonical data and never trusts client-supplied record fields. Live responses validate structure and citation IDs, but are still model interpretations that require source review. They are not silently replaced with a successful stored run.

The adapter is included in the public repository; the base weights are not redistributed. The base model's license and terms remain applicable. No benchmark result is a claim of guaranteed future performance or environmental benefit.

## Why a model here?

The map, field display, and resident briefing use deterministic code because structured inventory facts do not need a language model. The specialist experiment addresses a different input: a resident's natural-language claim about what those facts imply. Fine-tuning teaches a small local model to distinguish a matching fact, a conflicting fact, and a missing observation. This benchmark demonstrates that narrow behavior; it does not establish that an LLM outperforms a well-designed rule system on these templates. Broader phrasing and expert-reviewed cases are necessary before relying on it for general claim checking.
